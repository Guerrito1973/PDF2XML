## Project Overview

PDF2XML extracts tables from specific PDF files and converts them to structured XML. It is purpose-built for PDFs generated by "select.PDF for .NET v2017 17.3.0" that contain a `HISTORIAL CURSOS ClÍNICOS` section with clinical course tables.

## Setup & Commands

```bash
# Install dependencies (Python 3.7+)
pip install -r requirements.txt

# Process a single PDF
python pdf2xml.py archivo.pdf

# Process all PDFs in a directory
python pdf2xml.py --directory /ruta/a/directorio
# or
python pdf2xml.py /ruta/a/directorio

# Custom output directory
python pdf2xml.py --output resultados archivo.pdf

# Custom config file
python pdf2xml.py --config mi_config.json archivo.pdf

# Debug: verbose + log to file
python pdf2xml.py --verbose --log-file debug.log archivo.pdf
```

There is no test suite and no linter configured.

## Architecture

The entire application lives in a single file, `pdf2xml.py`, with one class: `PDFTableExtractor`.

### Processing pipeline (`process_pdf`)

1. **Unprotect** — `pikepdf` strips PDF encryption/restrictions and saves a `temp_<name>.pdf` in the output directory.
2. **Locate section** — `find_section_boundaries` iterates pages with `pdfplumber`, scanning extracted text for `section_start_marker` and `section_end_marker`. Returns zero-based page indices.
3. **Extract & merge tables** — `extract_tables_from_section` calls `pdfplumber`'s `page.extract_tables()` on every page in the range. Multi-page table continuation is detected by comparing the column count of the first row of a new table against the last row of the accumulator. If they match, rows are appended; otherwise the accumulated table is flushed and a new one begins.
4. **Serialize to XML** — `tables_to_xml` builds an `lxml` element tree. The first row of every table is treated as a header; subsequent rows become `<row>` elements with `<cell>` children carrying both `column` (1-based index) and `name` (header text) attributes.
5. **Cleanup** — the temporary unprotected PDF is deleted.

`process_directory` is a thin loop over `*.pdf` / `*.PDF` files that calls `process_pdf` for each.

### Configuration (`config.json`)

```json
{
  "section_start_marker": "HISTORIAL CURSOS ClÍNICOS",
  "section_end_marker": "Constantes",
  "output_directory": "output"
}
```

All three keys can be overridden: markers via `config.json`, output directory also via `--output` at runtime. The `PDFTableExtractor` constructor accepts an arbitrary config path.

### Programmatic use (`example_usage.py`)

`PDFTableExtractor` can be imported and used directly. `output_dir` is a mutable attribute that can be changed after construction.

## Key Constraints

- PDFs must have **searchable text** (not scanned images). Scanned PDFs require OCR pre-processing before this tool can work.
- Section markers must match **exactly** as they appear in the PDF, including diacritics (`ClÍNICOS`).
- Multi-page table merging relies solely on **column count equality**. Tables on consecutive pages that happen to have the same number of columns will be merged even if they are semantically distinct. This is a known heuristic limitation.
- The output XML filename is derived from the PDF stem: `output/<stem>.xml`.
